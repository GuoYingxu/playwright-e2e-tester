# E2E 测试覆盖率统计

统计两个维度的覆盖率并写入 `e2e/plan.md` 的 `## 覆盖率概览` 区块。

**纯静态分析，无需运行项目，无需 MCP 浏览器。**

---

## 工作流程

### 阶段 0：检查 plan.md 是否存在

```text
⚠️ 未找到 e2e/plan.md，请先运行 /e2e-automation:e2e-plan 生成测试计划
```

如果 `e2e/plan.md` 不存在，终止并提示先运行 `/e2e-plan`。

### 阶段 1：维度一 — 计划覆盖率

读取 `e2e/plan.md`，解析 Markdown 结构提取数据。

#### 解析方法

1. 找到所有 `### /路由路径 — 页面名称` 的二级标题
2. 在每个标题下找到 `| # | 测试用例 | 代码 |` 表格
3. 遍历表格行，统计 ✅（已生成）和 ❌（未生成）的数量
4. 如果页面的所有用例都是 ✅，该页状态标记为 `✅ 已完成`
5. 如果部分 ✅，状态标记为 `🔄 部分完成`
6. 如果全 ❌，状态标记为 `❌ 未开始`

#### 输出格式

```
📊 计划覆盖率:

| 页面 | 用例数 | 已完成 | 状态 |
|------|--------|--------|------|
| /login | 3 | 3/3 | ✅ |
| /user/profile | 4 | 2/4 | 🔄 |
| /product/list | 5 | 0/5 | ❌ |
| **总计** | **12** | **5/12 (41.7%)** | |
```

#### 参数过滤

如果用户指定了页面参数（如 `/e2e-coverage 登录`），只统计文件名或路由名匹配的页面。匹配方式：页面路由或名称包含参数字符串即视为匹配。

### 阶段 2：维度二 — 路由覆盖率

#### 2.1 发现项目路由

**复用 `/e2e-plan` 阶段 1 的路由发现逻辑**，扫描项目源码识别所有路由：

1. 读取 `package.json` 了解技术栈
2. 扫描以下目录识别页面/路由文件：
   - **Vue 项目**：`src/views/`、`src/pages/`、`src/router/`、`/pages/`
   - **React 项目**：`src/pages/`、`src/routes/`、`app/`、`src/App.tsx`
   - **Next.js**：`app/`（App Router）或 `pages/`（Pages Router）
   - **Nuxt**：`pages/`
   - **Angular**：`src/app/` 下的路由配置
   - **通用**：`src/router/`、`src/routes.ts`、`src/router.ts`
3. 读取路由配置文件，理解 URL 路径与组件的对应关系
4. 输出路由清单

#### 2.2 扫描已有测试文件

使用 `glob` 或 `read_file` 列出 `e2e/tests/` 下的所有 `.spec.ts` 文件。

#### 2.3 路由匹配规则

**模糊匹配**，不要求文件名与路由名完全一致：

| 测试文件名 | 匹配方式 |
|-----------|---------|
| `login.spec.ts` | 去掉 `.spec.ts` 后缀 → `login` → 匹配 `/login` |
| `user-profile.spec.ts` | 去掉后缀 → `user-profile` → `-` 替换为 `/` → `user/profile` → 匹配 `/user/profile` |
| `product-list.spec.ts` | 去掉后缀 → `product-list` → 匹配 `/product/list`、`/products` 等包含关系 |

匹配逻辑：
1. 去掉 `.spec.ts` 后缀
2. 将 `-` 替换为 `/`
3. 检查路由路径是否**包含**该字符串（不要求完全相等，避免 `/product/:id` 这种带参数路由匹配不上）
4. 一个路由只能匹配一个文件，一个文件可以匹配多个路由（先匹先得）

#### 2.4 参数过滤

如果用户指定了参数，只统计匹配的页面路由的覆盖率。

#### 输出格式

```
📊 路由覆盖率:

| 路由 | 测试文件 | 状态 |
|------|---------|------|
| /login | login.spec.ts | ✅ |
| /user/profile | user-profile.spec.ts | ✅ |
| /product/list | — | ❌ |
| /product/:id | — | ❌ |
| /order/detail | order-detail.spec.ts | ✅ |
| **总计** | **3/5 (60%)** | |
```

### 阶段 3：写入 plan.md

在 `e2e/plan.md` 的 `## 页面清单` 标题**之前**插入（或替换已有的）`## 覆盖率概览` 区块。

#### 写入规则

1. 先检查 `## 覆盖率概览` 是否已存在于 plan.md 中
2. **如果已存在**：定位到该区块的起止位置（从 `## 覆盖率概览` 到下一个 `##` 或文件末尾），用新内容替换
3. **如果不存在**：在 `## 页面清单` 标题前插入新区块
4. 区块内容格式如下：

```markdown
## 覆盖率概览

| 维度 | 指标 | 数值 |
|------|------|------|
| 计划覆盖率 | 已完成用例 / 总用例 | 5/12 (41.7%) |
| 路由覆盖率 | 已覆盖路由 / 总路由 | 2/3 (66.7%) |

---

```

**注意**：
- 数值用粗体表示（如 `**5/12 (41.7%)**`）
- 如果计划覆盖率 = 100%，数值后加 `🎉`
- 区块后保留一个 `---` 分隔线，再继续 `## 页面清单`
- 不要破坏 plan.md 中 `## 页面清单` 及之后的内容

### 阶段 4：输出结果

```
✅ 覆盖率统计完成！

📊 计划覆盖率: 5/12 (41.7%)
   /login         — 3/3  ✅
   /user/profile  — 2/4  🔄
   /product/list  — 0/5  ❌
   /order/detail  — 4/4  ✅
   /settings      — 3/4  🔄

📊 路由覆盖率: 3/5 (60%)
   已覆盖: /login, /user/profile, /order/detail
   未覆盖: /product/list, /product/:id

📄 覆盖率已写入 e2e/plan.md

   💡 运行 /e2e-generate 生成未完成的用例来提高覆盖率
```

---

## 注意事项

1. **纯静态分析**：不需要启动项目，不需要 MCP 浏览器，无需登录
2. **不修改 plan.md 的其他内容**：只插入/替换 `## 覆盖率概览` 区块，页面清单和用例表格不动
3. **路由匹配要宽松**：带参数路由（如 `/product/:id`）不应因为文件名不包含 `:id` 就被判定为未覆盖。文件名 `product-list` 应能匹配到 `/product/list` 和 `/product/:id`
4. **异步统计**：如果用户先 `/e2e-generate` 生成了代码（更新了 ✅ 状态），再跑 `/e2e-coverage` 才能反映最新进度
5. **如果参数过滤后只有一个页面**：也按完整格式输出，总计行只显示该页数据

## 示例

```
/e2e-automation:e2e-coverage                 # 统计所有页面的覆盖率
/e2e-automation:e2e-coverage 登录            # 只统计"登录"相关页面
/e2e-automation:e2e-coverage /user           # 只统计 /user 路由下页面
```
